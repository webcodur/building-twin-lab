# 대상 기업 맞춤 PoC 아이디어

대상 기업은 공개 기사(2025.09~2025.12)로 파악했다. 이 문서는 기업명을 쓰지 않는다. 조사 출처는 저장소 밖에 둔다.

## 1. 대상 기업 요약

| 항목 | 내용 |
|---|---|
| 정체성 | AI 기반 건물 에너지 최적화 스타트업. 2022년 설립, 서울. 소규모 팀 |
| 핵심 제품 | 건물 운영 자동화 플랫폼. 냉난방공조(HVAC)를 AI로 자율 제어한다 |
| 도입 방식 | 기존 BMS와 데이터만 연동한다. 대규모 설비 교체 없이 들어간다 |
| 공개 성과 | 에너지 15~30% 절감, 쾌적도 98% 수준 |
| 기술 축 | 강화학습 기반 시뮬레이션 엔진, 온디바이스 제어, 공간+설비 통합 분석 |
| 건물 DX 자동화 | 도면·이미지를 인식해 3D 모델로 변환한다. 데이터당 최대 10만 점의 고정밀 포인트클라우드(PCD)를 구축해 건물 외형·구조 인식 파이프라인을 만들었다 |
| 시장 | 국내 + 유럽. 프랑스 부동산 회사와 주거 리노베이션 PoC(시뮬레이션상 에너지 20%·탄소 25% 감축), 유럽 ESG 건축 시장 진출 |
| 성장 신호 | 글로벌 팁스 선정, 바르셀로나 스마트시티 전시 참가, 데이터바우처 우수사례 수상 |
| 협력 | AI 데이터 보호 기업과 MOU. 데이터 무결성과 운영 안정성을 강조한다 |
| 비전 | 건물 단위에서 도시·국가 단위 에너지 자율 운영으로 확장 |

## 2. 이 회사에 3D가 필요한 이유

이 회사의 가치는 "AI가 알아서 아낀다"에 있다. 그런데 운영자 입장에서 그 말은 블랙박스다. 3D는 화려함이 아니라 **설명·온보딩·영업**의 도구로 쓸 때 값어치가 있다.

1. **신뢰(설명 가능한 제어)**: AI가 어느 존을 왜 그렇게 제어했는지 공간 위에 보여 준다. 운영자가 AI 제어를 켜 둘지 말지가 여기서 갈린다.
2. **도입 장벽 제거**: 고객 건물을 도면·스캔으로 즉시 3D화한다. 이 회사가 이미 투자한 "건물 DX 자동화"의 결과물을 고객이 눈으로 확인하는 첫 화면이다.
3. **유럽 리노베이션·ESG 영업**: 외피 진단과 리노베이션 전후 비교를 3D로 보여 준다. 부동산 소유주·투자자가 이해하는 언어로 바뀐다.
4. **데이터 신뢰성**: 센서 결측·이상을 공간에 표시하고, 보간 중임을 숨기지 않는다. 데이터 보호 협력과 같은 방향이다.
5. **규모 확장 서사**: 한 동에서 포트폴리오, 도시로 이어지는 화면 하나로 비전을 보여 준다.

## 4. PoC 시연 시나리오 (15분)

1. **포트폴리오**(2분): 운영 중인 건물 전체를 원단위로 칠한다. 원단위가 높은 건물을 누르면 그 건물로 날아간다.
2. **디지털 트윈**(5분): 하루를 재생한다. 아침 예냉, 점심 재실 감소, 비어 있는 회의실 셋백을 3D로 보여 준다. 하단 그래프에서 두 곡선이 벌어지는 것을 보여 주고, 결측 센서 경보가 뜨는 순간 보간 중임을 설명한다.
3. **즉석 디지털화**(4분): 고객 건물 도면 이미지를 깔고 실을 그린다. 3D 매스와 방위별 외피 면적이 나오고 JSON을 내려받는다. 스캔 파일이 있으면 점군에서 벽을 추출한다.
4. **리노베이션**(3분): 현재 외피와 리노베이션 후를 열화상으로 비교한다. 연간 난방 부하 절감률을 숫자로 보여 준다.
5. **질의**(1분): 실제 데이터 연동 범위와 일정을 합의한다.

## 5. 실제 연동 구조 제안

```
[BMS·센서] ──포인트 목록──▶ [존 매핑 JSON] ──┐
[도면·스캔] ──자동 모델링──▶ [건물 모델 JSON/glTF] ─┼─▶ [웹 3D 뷰어(이 저장소의 core)]
[AI 엔진] ──시계열·제어 이력·근거──▶ [시계열 API] ──┘
```

- **존 매핑 JSON**이 핵심 계약이다. BMS 포인트 이름(예: `AHU-2.VAV-3F-S.ZoneTemp`)을 3D 존 ID에 묶는다. 이 파일만 있으면 어떤 건물이든 같은 화면이 돈다.
- 건물 모델은 처음에는 이 실험실의 `envelope.json`(실 사각형 + 층수) 수준으로 충분하다. 다음 단계에서 glTF·IFC로 넓힌다.
- 시계열은 화면이 직접 계산하지 않는다. 스텝 배열(현재 `ScenarioResult` 형식)로 받아 인덱스만 넘긴다.
- 화면 코어는 프레임워크에 묶지 않는다. React 대시보드에 넣을 때는 `mount(el) → dispose` 함수 하나를 감싸면 된다.

## 6. 일정 제안

| 기간 | 산출물 |
|---|---|
| 1~2주 | 실제 건물 1동의 존 매핑 JSON + 하루치 실측 시계열 리플레이(A, E, F) |
| 3~4주 | AI 제어 근거 표시(B), 도면 이미지 → 매스 → 외피 JSON(C), 임베드(L) |
| 5~8주 | 리노베이션 비교 보고서 출력(D), 포트폴리오 지도(H), What-if(I) |

## 7. 착수 전 확인할 것

- BMS 포인트 목록 형식(BACnet 객체 목록·CSV 등)과 존 구분 기준
- 자동 모델링 결과물의 출력 형식(자체 JSON, gbXML, IFC, 메시)과 좌표계·단위
- AI 엔진이 내보낼 수 있는 값: 설정온도 이력, 예측 재실, 결정 근거 코드
- 데이터 반출 범위: 브라우저로 원시 시계열을 내려도 되는지, 집계만 내려야 하는지
- 대상 단말: 관제실 대형 화면, 노트북, 태블릿 중 무엇이 주력인지(그래픽 예산이 달라진다)
- 유럽 고객용 지표: 에너지 성능 등급(EPC)·탄소 배출 계수 등 보고서에 들어가야 할 값

## 8. 실험실 수치의 성격

화면의 숫자는 모두 가상 건물과 단순 모델에서 나온 값이다. 시연에서는 "구조와 화면을 보여 주는 값"이라고 밝힌다.
- 하루 절감 26.2%, 쾌적 99.9% → 99.4%: 1R1C 존 열 모델, 재실 기반 외기 제어(DCV)·팬 변속·셋백·예냉의 합. 공개 성과 범위(15~30%) 안에 들도록 계수를 잡았다.
- 리노베이션 후 난방 부하 −68%: UA × 난방도일 근사. 환기·일사 취득은 뺐다.
